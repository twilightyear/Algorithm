### [ LeetCode ] 347. Top K Frequent Elements

### 📌 문제 링크

[LeetCode - Top K Frequent Elements](https://leetcode.com/problems/top-k-frequent-elements/description/)

### ⚠️ 제약조건

- 1 <= nums.length <= 105
- -104 <= nums[i] <= 104
- k is in the range [1, the number of unique elements in the array].
- It is guaranteed that the answer is unique.

### 🛠️ 풀이 접근 및 분석

> Given an integer array nums and an integer **k** , return the **k** most frequent elements. You may return the answer in any order.

-   **접근 1**

    - 문제를 보자마자 생각이 든 접근법은 **Set** 을 사용하여 중복되지 않은 요소들, 즉 유일한 값들에 대하여 **count** 한 데이터를 **2차원 배열** 에 **[[개수],[요소]]** 형식으로 저장하고, **[개수]** 를 기준으로 **내림차순으로 정렬** 한 배열에 대하여 앞에서부터 **k** 개를 추출하고 **[요소]** 인덱스에 해당하는 **1번 인덱스** 를 선택하여 최종적으로 이 값들만 모아서 반환하면 결과가 나올 것이라는 생각을 했다.
    - 여기서 **Set** 으로 만드는 과정에서 원본 배열의 숫자 개수 **N** 개에 대하여 전부 조회가 진행되어야하기 때문에 **O(N)** 의 시간복잡도를 가지며, 최악의 경우 **N** 개가 전부 다르면 **N** 개의 서로 다른 숫자를 따로 저장해야하기 때문에 **O(N)** 의 공간복잡도를 가지게 된다.
    - 이후에도 **Count** 도 전체조회를 진행하기에, 서로 다른 원소를 가진다고 해도 개수의 총합이 **N** 개라는 사실은 변하지 않고, 이에 대한 조회의 횟수도 변하지 않는다. 그렇기에 **O(N)** 의 시간복잡도를 가지게 된다. 이후 이 데이터들을 **2차원 배열** 에 **[[개수],[요소]]** 형식으로 저장하는 과정에서 최악의 경우 **O(N)** 의 시간/공간복잡도를 가지게 된다.
    - 이후 내림차순으로 정렬하는 과정에서 **Tim Sort** 가 사용된다. **O(NlogN)**  의 시간복잡도와 **O(N)** 의 공간복잡도를 가진다.
    - **k** 개에 대하여 정렬된 데이터의 특정 데이터를 추출한다. **1번 인덱스** 에 대한 추출은 **O(1)** 의 시간복잡도를 가진다. 값 **k** 에 대하여 **O(K)** 의 시간/공간복잡도를 가진다.
    - 결론적으로 **접근 1번** 은 **O(NlogN)** 의 시간복잡도와 **O(N)** 의 공간복잡도를 가지는 코드라고 분석해볼 수 있었다.

-   **접근 2**

    - 위의 풀이가 다른 사람들의 풀이와 비교해봤을때 상당히 비효율적이라는 사실을 보고 많은 고민을 했다. 결국 **Sort** 부분에서 시간복잡도가 커진다는 점에 주목하여 앞부분은 그대로 두고 뒷 부분의 알고리즘 구성을 달리 해볼까라는 생각을 중점으로 접근했다. 물론 앞부분의 2차원 배열의 형태로 **Counter** 로 구현한 부분도 **Collections** 의 **Counter** 를 사용함으로써 최적화를 진행하였다. 

    - 뒷 부분에 대해서는 **Sort** 역할을 해줄 수 있는 대역이 없을가 생각을 하다가 우선순위 **Queue** 의 적용이 어떤가 싶었으며, 실제로도 상위권 풀이가 어떻게 되었는지 힌트를 조금 얻는 과정에서 **Heapq** 가 사용된것을 보고 접근법을 구상할 수 있었다. 앞부분의 원리는 똑같이 구성하되, **빈도** 와 **값** 에 대하여 빈도를 우선순위로 두고 **(빈도, 값)** 을 추가하여 **pop** 하면 빈도가 가장 낮은 값만 **k** 번 추출이 가능하다는 사실에 중점을 두었다. 하지만 이렇게 그대로 구현하면 가장 많이 등장하는 값이 아니라 적게 등장하는 값이 나타나게 될 것이다. 그렇기에 **(-빈도, 값)** 을 사용하여 빈도가 가장 많이 등장하는 수가 더 작은 수가 되어서 적절하게 추출 될 수 있을 것이다.

    - 원소의 개수 **N** 개에 대하여 **Count** 하는 과정은 **O(N)** 의 시간복잡도와 **O(N)** 의 공간복잡도를 가지는 것은 동일하다. 다만 위의 코드보다는 오버헤드와 상수항 만큼의 시간/공간의 비효율성이 개선된다는 점이 있을 것이다. **Heap** 을 구성하는 단계에서 **Heapify** 는 **O(N)** 의 시간/공간복잡도를 가진다. 이외에도 **Heappush** 과 **Heappop** 은 최악의 경우 **O(logN)** 의 시간복잡도와 **O(NlogN)** 의 공간복잡도를 가진다.


### 📝 추후 개선점

- **Collections** 의 **Counter** 를 사용하여 필요없는 구현라인을 제거하여 오버헤드 발생을 줄였으며, **Heapq** 를 사용하여 우선순위큐를 이용할 수 있었다. 하지만 본 코드에서 빈도에 음수를 붙이지 않고, **Min Heap** 의 특성을 그대로 가져가며 효율을 높힐 수 있다라는 방향의 접근법도 알 수 있었다. **K** 에 대하여 **Heap** 의 크기가 **K** 를 넘어서면 **Heappop** 하여 우선순위가 낮은, 즉 빈도 자체가 낮은 값을 사전에 제거하여 결국 **K** 개의 값만 유지하며 결론적으로 빈도가 높은 두 값만 남는다는 접근법이 존재했다. 이 접근법으로는 최악의 경우 발생할수 있는 **O(NlogN)** 의 시간복잡도가 **K** 값에 대하여 **O(KlogN)** 으로, **K** 값은 제약조건에서 최악의 경우 **N** 이지 평균적인 상황에서는 **N** 보다 작을 것이기 때문에, 복잡도 측면에서도 개선점이라는 것을 파악할 수 있다.

### 💻 풀이 코드

```python
#풀이 1 (Set & Sort)

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        data = set(nums)
        arr = []
        result = []

        for item in data: #유일한 원소들에 대하여 [[개수],[원소]] 의 형식으로 저장
            arr.append([nums.count(item),item])

        arr.sort(reverse=True) #내림차순 정렬

        for i in range(k):
            result.append(arr[i][1]) #k개만큼 앞에서 추출

        return result
```

```python
#풀이 2 (Dictionary & Heap(Priority Queue))

import collections
import heapq

class Solution:
    def topKFrequent(self, nums: List[int], k: int) -> List[int]:
        priority_queue=[]
        result=[]
        heapq.heapify(priority_queue)

        for num, freq in collections.Counter(nums).items(): #Dictionary 를 이용한 Counter
            heapq.heappush(priority_queue, (-freq,num)) #우선순위를 음수화 하여 역우선순위로 저장

        for i in range(k):
            result.append(heapq.heappop(priority_queue)[1]) #우선순위가 높은, 즉 음수를 취하기 전의 의미로는 우선순위가 낮은 원소들을 추출
        
        return result
```
